# thirdPerson Crypt Scene Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A torch-lit stone maze scene (`CryptScene`) in `examples/thirdPerson`, reachable by
deep link `scene=crypt`, that the knight can walk through and leave, at 20 fps on the Roku Ultra.

**Architecture:** A text grid (`CryptMap`) is the single source of the maze: it yields solid
cells (walls, colliders, `SolidWorld` solids), wall faces, torch and prop spots, the start and
the exit. Each solid cell bordering floor is one static `CryptBlock` entity whose faces are
2 m wall segments, drawn either as oriented images or as one textured `DrawableModel`
(deep link `walls=image|model`). Shared knight/camera/HUD setup moves from `FieldScene` into
a `ThirdPersonScene` base class both scenes extend.

**Tech Stack:** BrighterScript (bsc 1.0.0-alpha.57), BGE engine, Python 3 + Pillow for art,
`rokubot` / `npm run run-example` for device runs.

**Spec:** `specs/2026-11-05-third-person-crypt-design.md`

## Global Constraints

- All paths below are under `examples/thirdPerson/` unless they start with `src/source/engine`.
- World scale: `World.UNITS_PER_METRE` = 32; use `World.metres()` for every distance.
- Grid cell 6 m (corridors 5-6 m wide); maze about 8 x 8 cells, about 50 m across.
- Wall height 4 m; wall faces cut into 2 m segments (3 per 6 m cell side).
- No engine changes. If the target can't be met without one, stop and report.
- Example code has no unit-test harness and `npm run check` doesn't cover it. Each task's
  gate is `npm run build` in `examples/thirdPerson` (bsc type-check, zero errors) plus, where
  stated, a device run with the `rokubot-examples` skill on the Ultra (192.168.41.102).
- `FieldScene` must look and play exactly as before (default launch, existing deep links).
- All art is generated by our own scripts in `tools/`; nothing added to `CREDITS.md`.
- `bslint`: no single-line `if`; `import` every file whose symbols you use; prefer real types.
- Keep UI title-safe (≥10% from canvas edges).
- Lights never move or flicker.

## Review Focus

- Sliding along a wall into a corner, and dodging/lunging/knockback into a wall: the knight
  must never end up inside a solid cell (pinned by the Task 4 device check "dodge into every
  wall of the start corridor").
- Camera near walls and at max tilt: must never show the far side of a wall or the void
  above the maze (Task 6 device check "orbit and tilt fully against a wall").
- Leaving the crypt then relaunching `scene=crypt`, or dying in the crypt: no leaked lights,
  bitmaps or stuck `SolidWorld` state (Task 6 device check with the debug memory panel).
- Launching with no deep link: `FieldScene` unchanged (Task 2 device check).
- Unknown `walls=` value falls back to the default style, not a crash (Task 3 step).

### Task 3: CryptMap and CryptBlock

**Files:**
- Create: `src/source/Crypt/CryptMap.bs`, `src/source/Entities/CryptBlock.bs`

**Interfaces:**
- `CryptMap.bs`, `namespace CryptMap`:
  - `const CELL_METRES = 6`, `const WALL_METRES = 4`, `const SEGMENT_METRES = 2`
  - `function layout() as string[]` — the maze rows. Legend: `#` solid, `.` floor,
    `S` start (floor), `E` exit doorway (floor; on the border), `T` floor cell with a torch
    on one of its walls, `A` altar (floor), `k` skeleton alcove, `r` rubble, `b` bones
    (all floor). Row 0 is the far (−z) edge; column 0 is −x. The outer ring is `#` except `E`.
    About 9 x 9 cells, a few dead ends and loops, `E` not visible from `S`.
  - `interface CryptCell extends roAssociativeArray` { `col as integer`, `row as integer`,
    `kind as string` }
  - `function parse(rows as string[]) as CryptLayout` with
    `interface CryptLayout extends roAssociativeArray` { `cols as integer`, `rows as integer`,
    `cells as CryptCell[]` (every non-`#` cell), `solids as CryptCell[]` (every `#`),
    `start as CryptCell`, `exit as CryptCell` }
  - `function cellCenter(col as integer, row as integer) as BGE.Math.Vector` — world x/z
    centre, y 0, origin at the grid centre.
  - `function isSolid(layout as CryptLayout, col as integer, row as integer) as boolean` —
    outside the grid counts as solid.
- `CryptBlock.bs`, `class CryptBlock extends BGE.GameEntity`, `isStatic = true`:
  - `onCreate(args)` args: `x`, `z` (cell centre), `openSides as string[]` (subset of
    `"n","e","s","w"` bordering floor; n = −z), `style as string` (`"image"` or `"model"`;
    anything else = `"image"`).
  - `"image"`: for each open side, 3 `addImage` segments from the `cryptWall` region,
    `drawMode: oriented`, facing outward from the cell, `isShaded: true`,
    `isOccluder: true`, anchored bottom-centre, 2 m apart along the side.
  - `"model"`: one `DrawableModel` with two triangles per segment per open side, each face
    textured with `BGE.Model3dTexture` over the `cryptWall` region (UVs 0..1), outward
    normals, CCW from outside (see `Pillar.buildBoxModel`), `isShaded: true`,
    `isOccluder: true`.
  - One `addBoxCollider3d("body", cell, wallHeight, cell, 0, wallHeight/2, 0)` with
    `memberFlags = World.CAMERA_BLOCKER`.

- [ ] **Step 2:** Write `CryptBlock.bs`.

### Task 4: Keeping the knight out of walls

**Files:**
- Create: `src/source/Crypt/CryptWalls.bs`

**Interfaces:**
- `class CryptWalls`:
  - `sub new(layout as CryptLayout)` — builds a `BGE.SolidWorld` with one solid per `#`
    cell (world x/z mapped to SolidWorld x/y, bottom-left corner).
  - `sub track(fighter as Fighter)` — remembers the fighter and its current position.
  - `sub resolve()` — for each tracked fighter, `moveAndSlide` a square feet box of side
    `2 * fighter.bodyRadius` centred on the remembered position by the frame's delta
    (`position − remembered`), writes the result back to `position.x/z`, and remembers it.
  Called after every body has moved (knight movement, knockback, separation), so one place
  covers all of them.

### Task 5: CryptScene, deep links and first device run

**Files:**
- Create: `src/source/Scenes/CryptScene.bs`, `src/source/Entities/CryptProp.bs`,
  `src/source/Entities/CryptDoorway.bs`
- Modify: `src/source/main.bs`

**Interfaces:**
- Consumes: Task 1 bitmaps, `ThirdPersonScene`, `CryptMap`, `CryptBlock`, `CryptWalls`, `Torch`.
- `class CryptProp extends BGE.GameEntity`, `isStatic = false`; args `x`, `z`, `bitmap`
  (bitmap name), `height` (metres); one `axisAligned` image, base on the floor, `isShaded`.
- `class CryptDoorway extends BGE.GameEntity` (in `src/source/Entities/CryptDoorway.bs`):
  args `x`, `z`, `heading`, `width` (metres, default 4); a post-and-lintel `DrawableModel`
  (two 0.6 m square posts, 3.5 m tall, and a 0.6 m lintel across the top), flat stone
  colour, `isShaded`. Placed at `E` (in the gap in the outer wall) and framing the altar.
- `class CryptScene extends ThirdPersonScene`, `m.name = "CryptScene"`:
  - fields `wallStyle as string = "image"` (deep link `walls`), `walls as CryptWalls`,
    `private lights as BGE.Light[] = []`
  - `onLoad`: knight atlas + the six crypt bitmaps (skip any already loaded).
  - `onCreate(args)`: shaded tiled floor plane (`cryptFloor`, `groundTexelScale` 2);
    a `CryptBlock` per solid cell with ≥1 open side; one `AmbientLight` (cold blue-grey,
    intensity ~0.08, tuned on device) added via `game.addLight` and kept in `lights`;
    a fire `Torch` per `T` cell, on the cell's first wall side, 2.4 m up, 0.2 m out from
    the wall; a `spirit` `Torch` behind the altar; `CryptProp`s for `A`/`k`/`r`/`b`;
    `addKnight` at `start`, facing the open side; `setUpCamera(World.metres(24), 0.5, maxTilt)`
    with `maxTilt` low enough that the camera stays below the 4 m wall tops (tune on device);
    `walls = new CryptWalls(layout)`, `walls.track(m.knight)`.
  - `afterBodiesMoved`: `m.walls.resolve()`.
  - `onUpdate`: HUD update, director update; when the knight's cell is `exit`, call
    `m.game.changeSceneWithFade("FieldScene")` once; knight death respawns at `start`
    after `respawnSeconds` (3) as in `FieldScene`.
  - `onDestroy`: remove `lights`; `unloadBitmap` the six crypt bitmaps.
- `main.bs`: `defineScene(new CryptScene(game))`; deep link `scene=crypt` starts it
  (default `FieldScene`); add `walls` to the passed-through keys; update the deep-link
  comment.
